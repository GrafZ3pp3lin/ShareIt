# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

ShareIt frontend: a SolidJS SPA for uploading and sharing content packages (files/text), with optional OIDC login (unauthenticated visitors are guests) and client-side encryption by default of pasted text and files (one generated passphrase per package, which can be switched off).

## Commands

```bash
pnpm dev              # vite dev server on http://localhost:3001 (plain http; localhost is a secure context, so crypto.subtle works)
pnpm build             # tsc -b && vite build -> dist/
pnpm test              # vitest (watch mode)
pnpm test:ui           # vitest with UI
pnpm lint              # oxlint
pnpm lint:fix          # oxlint --fix
pnpm format            # oxfmt (write)
pnpm format:check      # oxfmt (check only)
pnpm knip              # unused exports/deps/files
pnpm generate:open-api # regenerate src/client from a *running* backend at http://localhost:5155/openapi/v1.json
```

Run a single test file: `npx vitest run src/shared/crypto/framed.test.ts`.

oxlint runs with type-aware linting enabled (`.oxlintrc.json` → `options.typeAware`) plus the `typescript` plugin. The backend is `tsrs`, the Rust port of TypeScript 7.1: it ships a `tsrs-lint` binary that oxlint prefers over `tsgolint`, so installing `tsrs` is what makes type-aware rules like `no-floating-promises` and `no-misused-promises` work — don't remove it from devDependencies. It only has beta releases, so the version is pinned exactly and `pnpm-workspace.yaml` exempts it from `trustPolicy`.
Run a single project: `npx vitest run --project unit` or `--project components`.

There are two Vitest projects (`vite.config.ts`):

- `unit`: `*.test.ts` / `*.spec.ts` files, `environment: 'node'` — pure logic (crypto, error mapping).
- `components`: `*.test.tsx` / `*.spec.tsx` files, `environment: 'happy-dom'`, setup file `src/tests/vitest-setup.ts` — Solid component tests via `@solidjs/testing-library`, plus anything needing a DOM (`XMLHttpRequest`, `localStorage`).

Tests are co-located next to the source file, not in a `__tests__` dir.

`generate:open-api` requires the backend to be running locally and serving its OpenAPI spec at `http://localhost:5155/openapi/v1.json` (see `orval.config.ts`) — it is not run from a checked-in spec file.

## Architecture

### Routing and app bootstrap

Routing is code-based via `@solidjs/router` (`createRouter`), not file-based.

- `src/index.tsx` → `src/app.tsx` → `src/app/providers.tsx` (`AppProviders`), which nests, in order: `ThemeProvider` → `I18nProvider` → `AuthProvider` → `Router` (the `createRouter` instance is the provider component).
- `src/app/router.tsx` creates the router from `routeTree` (`src/shared/routes/route-tree.tsx`).
- `src/shared/routes/route-tree.tsx` is the **single wiring point**: it declares the route tree (`defineRoutes`). The app shell uses `AppLayout` for `/` (composer), `/auth/callback`, `/links` (owner links list), `/imprint` and `/privacy`; the share shell uses `variant="share"` for UUID-only `/s/:packageId`; `*` renders `NotFoundPage` with the share shell. Features never self-register — this file is where a new route must be added.
- `src/app/layout.tsx` (`AppLayout`) is the shared chrome: header/nav + `{props.children}` + footer. The `upload`/`links` nav and auth controls only render for authenticated users in the app shell; the share variant hides both and keeps the brand + theme toggle.

### Feature module convention

`src/features/<name>/`:

- `pages/<name>-page.tsx` — the route-level component, one per entry in the route tree.
- `components/` — presentational components local to that feature.
- Feature-local state/context sits directly under the feature root, e.g. `src/features/auth/auth-context.tsx` next to `pages/`.

Features consume cross-cutting concerns from `src/shared/*` (`api`, `crypto`, `config`), `src/i18n` and the auth context in `src/features/auth/auth-context.tsx`; otherwise they don't reach into each other.

### Generated API client + wrapper

`src/client/**` is entirely generated by Orval (`orval.config.ts`, `pnpm generate:open-api`) — never edit it by hand. Orval calls go through the mutator in `src/shared/api/fetch-client.ts` (`customFetch`), which adds the runtime base URL and identity headers and returns the generated `{ data, status, headers }` shape. `src/client/**` is excluded from oxlint (`.oxlintrc.json`); app wrappers in `src/shared/api/` map that result shape to `ApiResult` with type guards (no assertions). `ApiResult` also carries `retryAfterSeconds` parsed from a 429 `Retry-After` header. Orval renders int64 fields as `number | string` — the `content.ts` wrappers narrow them to plain numbers.

The app never calls generated SDK functions directly except through `src/shared/api/`:

- `fetch-client.ts` — `customFetch()` is the Orval mutator. It adds the runtime API base URL and identity headers: DPoP + bearer for an OIDC user, and nothing for a guest (guests have no stored id). The unlock proof and upload token are attached per call: by `createPackage`/`uploadItem` and `getPackageDetails`, never globally.
- `content.ts` — `ApiResult` wrappers around the generated calls: `createPackage(request, unlockProof?)`, `uploadItem(packageId, item, uploadToken, onProgress?, signal?)` (raw binary PUT via XHR with real progress + `AbortSignal` cancellation; metadata rides in `X-Content-Kind`/`X-Content-Meta` headers and the upload scope in `X-Upload-Token`), `getPackageDetails(id, unlockProof, accessSession)`, `downloadContent` (buffered `Blob`), `downloadContentResponse` (raw `Response` for streaming saves), `listPackages`, `deletePackage`, `getUploadLimits` and `resolveShortCode`. `createPackage` attaches `X-Unlock-Proof` only in code mode; the upload token only exists after a create has succeeded, so it is never sent on create. It also narrows generated `number | string` int64 fields.
- `error-message.ts` — `getErrorMessage()` normalizes error shapes (string, `Error`, RFC7807 `ProblemDetails`, generic `{message}`) into a display string.

### Composer flow

`src/features/composer/use-composer.ts` owns one composer surface for text and files:

1. Generate the package id and one item id per text/file once per attempt.
2. The composer starts in `generate` mode. When a passphrase is set (the default), derive the package key from the id (`keys.ts`) and compute the unlock verifier.
3. `POST /package` with `Id`, `UnlockVerifier` (null when password-off) and, in code mode, `UseShortCode: true` plus the verifier in `X-Unlock-Proof`. The server returns the three-character locator plus a one-time `UploadToken` (stored as a hash server-side and bound to the package and nullable `user_id`). The composer keeps the token only in its in-memory partial state. The server enforces single use + a 10-minute TTL for code mode.
4. Per item: frame content + `meta` when protected, then `PUT /package/{id}/content/{contentId}` — one raw `application/octet-stream` body per request with `X-Upload-Token`, `X-Content-Kind`/`X-Content-Meta` headers, with progress/cancel and stable ids for retries. The API validates the token, headers and `Content-Length` before it reads the payload, and the browser streams the file from disk (unencrypted items are never read into JS memory). Files are encrypted slice-by-slice into 4 MiB frames, never as one plaintext buffer; sealing is deterministic, so retries are byte-for-byte idempotent.
5. The result shows the canonical `/s/{packageId}` link and, when protected, the `#s=` combined link plus the passphrase (shown once). Code mode instead shows only the combined six-character code (`ABC-234`) and never a link or separate passphrase: the server never learns the three-character client secret. The creating tab keeps the full code in `sessionStorage` until it expires so the owner links list can offer “copy code”; other tabs or devices only see `HasShortCode`. The upload token is dropped when the upload finishes.

Per-file size limits come from `GET /package/limits` (anonymous vs authenticated), applied when files are added **and re-checked at submit**, then enforced server-side while streaming. The composer never retries the create call: a failed create drops the partial state and the next attempt generates a fresh package id. The API only answers a repeated create with the existing package when the caller still presents its original `X-Upload-Token`; otherwise it is a `409`. Reusing an item id with a different kind/size/meta is a `409`.

### Share flow

`src/features/share/pages/share-page.tsx` is UUID-only. The code-entry form normalizes the six-character code, splits it into the three-character locator and secret, resolves the locator through `POST /package/code/resolve` and navigates to the UUID route with replace history. It carries the secret in router state, never in the URL, so salt derivation, the unlock proof, frame AAD and access-session storage always use the canonical package id and the share page unlocks without a password gate. The resolver never claims an access or exposes package metadata. A code-mode package that is wrong five times is expired by the server and resolves as gone.

`src/features/share/use-share.ts` is a `locked → unlocking → unlocked | invalid | gone` state machine. A plain link renders the gate with no request until submit; a `#s=` link derives the proof and fetches immediately (skeleton, no gate flash), then `history.replaceState` removes the fragment after success. `GET /package/{id}` carries `X-Unlock-Proof` plus any stored `X-Access-Session`; a valid session reuses the access instead of claiming another, and a wrong proof gets `401` before any access is counted. Text and file metadata are decoded per item; every item's bytes come through a session-authorized download (nothing is inlined), and framed ciphertext is decrypted frame by frame. Encrypted and unencrypted downloads share one path in `save-file.ts`: `response.body` pipes through the frame decryptor when protected, then into `showSaveFilePicker`'s writable where supported, or into a `Blob` collected from the plaintext chunks. The session token lives in `sessionStorage` for the package lifetime (15 minutes) and is never put in a URL. `access-session.ts` owns that storage helper; the server is the authority for expiry, and the helper clears the token on a download `401` or a `410`/`404` package-gone response.

### Auth (OIDC)

`oidc-client-ts`, authorization-code flow (no client secret, SPA).

- `src/shared/auth/oidc.ts`: `getOidcSettings()` returns `null` if `authAuthority`/`authClientId` are missing from runtime config — this is how auth is fully optional/disabled per-environment. `getUserManager()` memoizes a singleton `UserManager` (or `null`).
- `src/features/auth/auth-context.tsx`: `AuthProvider`/`useAuth()` wraps the manager with Solid signals (`user`, `isLoading`, `isAuthenticated`, `isEnabled`) and exposes `login()`, `logout()`, `handleCallback()`.
- `src/features/auth/pages/auth-callback-page.tsx` handles the `/auth/callback` route: calls `handleCallback()` then navigates to `/`.
- Client ID/authority/scope/redirect URIs are never hardcoded — always read through `getRuntimeConfig()`.

### Runtime configuration (build once, configure per-deploy)

The app is a static SPA that must be reconfigured without rebuilding per environment (dev/stage/prod), documented in `docs/runtime-config.md`.

- `index.html` loads `/env.js` (a plain script, before the module bundle) which sets `window.env`.
- `src/shared/config/runtime-config.ts`: `getRuntimeConfig()` resolves each setting as `window.env` value → `import.meta.env.VITE_*` fallback → built-in default, computed once at import time.
- `public/env.js` — dev default (`ApiBaseUrl: http://localhost:5155`, auth fields empty → OIDC disabled locally by default).
- `docker/env.template.js` + `docker/40-env.sh`: at container start, `40-env.sh` runs in nginx's `/docker-entrypoint.d/` and `envsubst`s real container env vars (`API_BASE_URL`, `AUTH_AUTHORITY`, `AUTH_CLIENT_ID`, `AUTH_REDIRECT_URI`, `AUTH_POST_LOGOUT_REDIRECT_URI`, `AUTH_SCOPE`) into `env.template.js` → `dist/env.js`. This is how one Docker image serves multiple environments.
- Keep secrets out of `env.js`/`env.template.js` — it's public in the browser.

### Security headers and CSP

The image sets no security headers. They belong to the edge, including the `Content-Security-Policy`, so the policy is a single static string there.

That only holds while the served HTML has **no inline `<script>` or `<style>`**: an inline block would pin a `sha256` hash into the edge config, which then has to be bumped by hand with the deploy and silently breaks the page when forgotten. Anything that must run before first paint goes in `public/` — see `public/theme.js`, loaded as a render-blocking classic script from `index.html`. Analytics is production-only: `index.html` carries the umami tag between `analytics:start`/`analytics:end` markers and `vite.config.ts` strips it for `pnpm dev`, because the first-party `/m` proxy only exists in Traefik.

### Client-side crypto (`src/shared/crypto/`)

One optional passphrase per package; one sealed format for text and files. The server stores opaque bytes only.

- `ids.ts`: `normalizeId` / `idBytes` — the single UUID formatting used by keys and AAD.
- `keys.ts`: `packageSalt(id)`, `deriveKeyBits(passphrase, salt)` (PBKDF2-SHA256, 150k, client constant), `unlockProof(key, id)` (HMAC verifier sent as `X-Unlock-Proof`), per-item `itemKey` / `metaKey` via HKDF, and `frameAad` (binds every frame to package, item, role, chunk index and final flag).
- `framed.ts`: the `SIE3` frame container — `seal`/`sealFrame` (deterministic 12-byte IV derived from the chunk index), `encryptFile` (slice-by-slice 4 MiB frames), `openFrames` (buffered decrypt) and `frameDecryptStream` (a `TransformStream` that only emits a frame's plaintext after its GCM tag verifies). `isFramed`/`sealedSizeOf` round it out.
- `meta.ts`: per-item `{ name, mime }` JSON, sealed with `metaKey` when protected; `buildMeta` / `parseMeta` / `encodeMeta` / `decodeMeta`, fallback `item-<n>` on invalid metadata.
- `item-content.ts`: `openItemContent` — session-authorized bytes, then open the envelope when sealed.
- `passphrase.ts`: `generatePassphrase` and `validatePassphrase`.

There is no legacy `SIE1`/JSON envelope reader.

### i18n

`@solid-primitives/i18n`, `src/i18n/i18n.tsx` (`I18nProvider`/`useI18n()`) + `src/i18n/en.ts` (only locale currently). Translation dict is namespaced by feature: `app`, `composer`, `options`, `result`, `gate`, `share`, `links`, `auth`, `errors`. `t('some.key', { placeholder })` supports `{{ }}` interpolation. No locale-switch UI is wired yet even though the store supports `setLocale`.

## Tooling conventions

- Relative imports must include explicit file extensions (`import/extensions` oxlint rule), e.g. `from './use-links.ts'`.
- oxfmt: single quotes, semicolons, no trailing commas, 120 print width, `arrowParens: always`.
- `src/client/**` is intentionally excluded from lint and from knip's unused-export checks — don't try to "clean up" the generated client.
